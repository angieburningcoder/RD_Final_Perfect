一、軟硬體研發的差異 緒論RQ1

  • 硬體：固定成本高，晶片一年半才上市，做錯轉彎難
  • 軟體：輕資產、成本是人，一天可出好幾版
  • 缺點是護城河低，所以要靠規模化、跑得快、轉得快

二、研發組織與協作 3.2RQ3

  • Engine Team 做核心技術，B、C 共用
  • B2C 研發重迭代；B2B 研發貼著 CSM、BD；QA 兩邊分開
  • CGO 不帶 RD，把膚質檢測、膚色鑑定等前線需求帶回研發

三、B2B 的起源：以 B 養 C 背景RQ3

  • C 端流量大，但廣告多會傷體驗，變現難
  • 萊雅、蘭蔻主動來談技術授權
  • B 端 SaaS 訂閱收入穩定，用來支撐 C 端研發

四、客製化 vs 標準化 RQ3

  • 客製化是「毒藥」，台灣軟體公司常因此長不大
  • 只在兩種情況接：指標性大客戶（香奈兒、萊雅），且做完能變成標準產品
  • 中小品牌開放 API；未來呼叫 API 的可能是 AI Agent

五、護城河與 Make-or-Buy RQ1RQ2 技術

  • Unfair advantage：近百萬筆彩妝 IP 資料庫＋最後一哩精確度
  • 通用圖像生成不自研，當 Aggregator 整合最好的外部模型
  • 資源集中保護核心，否則「盲目自研會變四不像」

六、AI 時代的研發人才 AI 寫 CodeKMO

  • 只會寫基礎 Code 的工程師會被淘汰
  • RD 轉向審查 AI 產出的 Code、架構設計、走到前線（類似 FDE）
  • KMO：組織給容錯空間；招募看學習動機與吸收新知的能力

開場與背景

小魚：學長早安，我是小魚，之前創客（車庫）的學妹。線上兩位是同組夥伴 Doris 跟宛云，我們都是清大科管所的，想請教學長關於研發管理的專題。

學長：早安你好，不好意思我剛運動完身上都在流汗。沒問題，請問有什麼想了解的？

硬體與軟體研發的差異

小魚：您之前在硬體大廠（做 GPU 晶片）待過，後來創立玩美移動。從軟硬體的角度來看，研發管理有什麼明顯的不同？

學長：這是一個大題目。硬體有一個固定的硬成本（Fixed cost）。例如我們做晶片，做完一塊要到台積電下單，可能就是 100 萬美金。如果回來發現有 Bug，那個成本非常巨大。而且時程（Schedule）很長，做一個晶片可能一年半以後才會上市。相對來說，硬體的風險比較大，彈性（Flexibility）比較小，還要有安全庫存的概念，要做很多的風險管理。軟體的話，它的成本就是「人」，屬於輕資產（Light asset）。軟體可以非常快地迭代，我們甚至一天內可以出好多個版本去修復。但是軟體的缺點是護城河較低，人家很容易 Copy 你。所以規模化（Scale）很重要，你要跑得非常快，而且如果跑錯方向，要能夠很快轉彎。

研發組織架構與市場對接

小魚：玩美移動的研發組織大概是怎麼分類的？您作為成長官，是怎麼與研發團隊互動的？

學長：我們的技術分成幾個板塊。首先是核心技術（Core technology），像是人臉追蹤、膚質檢測等，這個團隊叫做 Engine Team。核心技術是 B2B 和 B2C 兩邊都可以共用的。另外，我們會分成做 B2C 的工程師和做 B2B 的工程師。B2C 專注在介面優化、使用者互動，需要很快的迭代；B2B 則因為要做客製化，工程師必須跟 CSM（客戶成功團隊）和 BD（業務）很緊密地接觸，去了解客戶需求。除此之外，QA 團隊也會分開，有專門測試 App 的，也有專門測 B 端的。至於我的參與，我沒有直接去帶 RD，但我會把市場未來的走向帶回來。例如我們現在主力產品「膚質檢測」、「膚色鑑定」，完全是從客戶那邊來的需求。我看到前線的市場需求，就會把觀念與戰略帶回去給 RD 去開發。

B2B 商業模式與客製化策略

小魚：說到 B 端，那時候是怎麼判斷 B 端市場有機會的？

學長：一開始我們做 C 端雖然流量很大，但在變現上遇到困難，因為廣告放太多用戶會不高興。剛好那時候像巴黎萊雅（L'Oréal）等美妝大廠來問我們能不能授權技術給他們。我們去談了之後發現，B 端走 SaaS 訂閱制的收入比較穩定，所以我們就開始用 B 端的收入來養 C 端的研發，兩邊互相補足。

小魚：那公司在處理 B 端需求時，是如何在「客製化」與轉向「標準化（API 化）」之間做取捨的？

學長：客製化這個東西，對做產品的軟體公司來說是「毒藥」。台灣很多軟體公司最後長不大，就是因為做了太多客製化，最後變成專案公司。所以我們對客製化是有策略性的。通常我們只接非常大、具備市場指標性的客戶（例如香奈兒等），因為金額不錯加上有指標意義。但最重要的是，我們幫他們客製化完，會把這個功能變成我們的標準產品（Standard product），繼續推廣給其他廠商用。現在我們大推 API 開放，是因為市場上有很多中小型客戶，我們沒那麼多資源去一對一服務他們，不如開放 API 讓他們自己去串接。未來的軟體趨勢可能客戶不再是「人」，而是客戶端的 AI Agent 直接寫 Code 來呼叫我們的 API。

技術護城河與外部模型（Make-or-Buy）

小魚：在生成式 AI 普及後，玩美有哪些核心技術是比較難被模仿，具有競爭優勢的？

學長：有些東西不是說給你一年兩年就能做到的，這就是我們的「不平等的競爭優勢（Unfair advantage）」。舉例來說，我們有將近一百萬筆的彩妝 IP Database（資料庫），這是我們花了很多年去跟品牌打交道才建立起來的，別人就算有錢也拿不到這個授權。第二個是「精確度」。現在的開源工具很多人可能可以做到 80% 像，但真正的品牌大廠在乎的是最後那一步，你的試妝到底能不能完美貼合（Fit）消費者的臉孔。這個最後一哩路（Last mile）的精確度，是別人很難追上的。

小魚：面對外部不斷進步的 AI 模型，公司怎麼決定哪些要自己做，哪些用外面的？

學長：這是戰場在哪裡的問題。每個公司有自己的專精，我們專精在美妝、服飾試穿的垂直領域。我們沒有必要去重練底層的通用圖像生成模型，所以我們選擇去整合（Aggregator）市面上最好的開源或外部模型，把它包進我們的架構裡。我們要把資源用在保護最核心的技術，否則盲目自研會變成四不像。

AI 時代的研發人才轉型

小魚：最後想請問，在 AI 普及後，RD 的工作型態與組織人才需求有什麼改變？

學長：現在 AI 自動寫 Code 的能力很強，寫 Code 的基礎工作大幅減少了。如果工程師只會寫基礎的 Code，未來很容易被淘汰。RD 以後的工作會越來越像 PM 加上審查者，AI 寫完 Code 後，你需要有能力去 Verify（驗證）邏輯對不對，並了解客戶痛點，把技術應用在前線的實際場景（類似 FDE 概念）。這時候，人的「動機（Motivation）」變得非常重要。技術變化太快，組織（Organization）必須提供好的支援，而 HR 要找的不再只是具備單一技能的人，而是具備強烈動機、能夠不斷去獲取新知識（Knowledge acquisition）的人，才能適應並抓住未來的每一個機會。
